- 避免：反复点击和清理不应是唯一进展；给轻养成提供离线安全、批量收取和不同收集目标。
- 验证深度：web open 作者玩法与控制说明；Run game 和 HTML5 可见，未启动游戏。
- Web 入口证据：页面第 7 行为 Run game，平台元数据为 HTML5。与 Raideraik 同名作不是同一作品；作者、网址、2D/3D 技术与机制均不同。

## 五个结论

1. 缺席安全应是默认：不掉好感、不饿死、不损坏已建内容。Cat Cove Inn 的寄存保护值得借鉴，但不应让玩家先学会保护自己；Tamaweb 页面评论展示了缺席死亡带来的负担。

2. 主循环采用短探索带回资源，再永久改变家园：Driftline 的打捞/设施链和 Spring Lullaby 的场景恢复，比只有计数器增长更易感知。一次返回要能看到一块新土地、一件摆设或一位新伙伴。

3. 把随机性留在奖励与选择，把长期成果保住：Marufuwa 的图鉴和水族箱、Tiny Islands 的地图成果都支持可见收藏；局内失败不清空长期家园，并给未收集物保底途径。

4. 自由观看和少量主动操作并存：KittyToy 的访客、Isla 的自然城镇、Bunbons 的伙伴互动让玩家可以闲看；主动探索建议只需 2–5 分钟，不设连续签到和高频奖励弹窗。

5. 保存与手机操作要先于内容数量：每次有效动作保存、备份导出、刷新/后台恢复、显式卡牌说明和足够大按钮。Driftwood 的逐动作保存和 Cardening 的悬停/旋转反例直接指导实现。
