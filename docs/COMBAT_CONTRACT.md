# Cutlass Wake · 当前遭遇战斗契约

更新时间：2026-10-24（北京时间）。范围仅为主角、一名持刀水手、一名火枪手、固定火炮、两层甲板与出口的可重玩遭遇。依据 `HANDOFF-PLAYTEST-2026-10-24.md` 和 `DESIGN-REFINEMENT-2026-10-24.md` 第4–6节实现；不包含 Boss、章节、存档或完整冒险完成声明。

## 修改前确实复现的行为

在修改前的纯模型隔离测试中，仅将英雄与持刀敌摆到对峙距离，停用火枪手以排除远程干扰。这是明确的测试 fixture，不是自然路线录像：

- 连续举刀15秒，刀兵兑现13次攻击、全部普通挡住，英雄仍6HP，没有破防事件。旧“最近2秒第三挡”与敌人约1.17秒的出招周期不匹配。
- 每25 tick再按一次第一刀，实际3次有效轻击杀死原3HP刀兵，英雄仍6HP；刀兵的起手持续被重新开始。

新测试独立覆盖长按防御、重复第一刀以及“第一刀命中→取消防御→再出第一刀”。没有把旧静态判断直接当作当前缺陷。

## 时间、坐标与接口

- `step(model, input)` 每次只推进一个60Hz tick；`FIXED_MS=1000/60`。渲染层负责 accumulator。模型不读取 RAF、系统时间或渲染帧率。
- 世界640×360；脚底坐标原点左上、向右/向下为正；地面255、墙18/622。英雄、刀兵、火枪手站姿碰撞与受击高68，宽分别22/26/22；闪避期间按实际身体帧改变高度，结束恢复68并再次检查合法落点。
- 新版当前idle实际alpha高度三人均为70px，统一68只留2px顶部发饰容差。旧58会忽略12px可见头部，且顶台时可见顶部能穿入12px横板。
- 木箱 `(160,231,48,24)`；高台横板 `(430,207,112,12)`。两者均为实体。68px站姿不能钻入横板下方，需跳上去；火炮弹线能从横板下的实际空隙通过。美术斜撑不等于整块封闭碰撞舱体。
- 主角初始6HP；刀兵4HP，火枪手3HP。增加刀兵1HP的用途是让一次明确的护身后撤有机会发生，不用大血量制造时长。
- 保留 `createModel`、`step`、`restart`、`setPaused`、`setFocused`、`snapshot`。新增 `getContextAction(model)` 和 `ContextAction` / `Opportunity` / `BufferedInput` 类型。

`Input` 保留 `move`、`jumpPressed`、`attackPressed`、`guardPressed`、`guardHeld`、`dodgePressed`、`interactPressed`，新增可选 `contextIntent`。J始终攻击/追击；E执行当前显示的上下文动作。旧“朝敌+J自动推击”已经取消。

## E必须绑定按下时所见意图

`model.contextAction` 和 `snapshot().contextAction` 的结构为：

```ts
{
  kind: 'none' | 'shove' | 'cannon',
  targetId: string | null,
  opportunityId: number | null,
  revision: number
}
```

渲染层用它显示“推撞”或“点炮”。在真实E/触控互动按下沿复制该对象，再将原副本随本次 `interactPressed` 传入 `contextIntent`。`getContextAction(model)` 返回独立副本。短缓存内不得重新计算或替换目标。兼容调用若不传副本，模型使用上一tick已经公布的显示意图；生产输入层仍应显式复制。

- J保留目标中心距离≤88px、中心高度差<46px的机会选择，实际挥刀仍可能落空。E另检查该目标碰撞框是否与任一实际active前掌点的2px接触范围相交；仅满足宽泛机会距离不会显示“推撞”。当前两个前掌脚相对点约为 `(38.735,-53.676)`、`(35.968,-53.538)`，不能拿持刀的后手替代。
- 否则仅在火炮idle、水平距离≤58px、脚底高度差≤30px时显示点炮。
- 推撞意图执行时核对机会ID、目标ID、时限、方向和真实前掌可达性。目标离开、死亡、机会刚到期或变成另一机会，只产生 `contextMiss`，不回落点炮。准备后目标再移开会真实挥空，不用吸附或额外位移补偿。
- 一个按下沿最多执行一次。持续给同一个 `interactPressed=true` 不会在火炮冷却后再次点火；必须释放后再次按下。
- 新输入可以覆盖唯一缓存，但不能将缓存内的E意图改成另一个目标或动作。

## 机会的来源与消费

`hero.opportunity` 为 `{ id,targetId,source,enemyActionId,expiresAt,facing }`，当前持续950ms。`source` 只有三种：

1. `parry`：正面可防近战的合法精准招架，绑定该敌人的真实攻击事件ID。
2. `whiffPunish`：刀兵真实挥空后，在明确收势内被玩家轻击命中，绑定该次挥空攻击ID。
3. `reloadInterrupt`：玩家命中火枪手正在发生的装填动作，绑定该次装填动作ID。

普通命中、炮击、枪击、推撞以及第二人被撞断起手都不会生成机会。`hero.parryTarget` 暂留为该机会的旧UI兼容镜像，新逻辑应读取 `opportunity`。

- J在目标正面可达时选择追击，消费这次机会，命中指定目标造成2伤害；没有机会的普通轻击为1伤害。机会不会转成对其他人的额外伤害。
- E选择推撞，消费机会并锁定目标；120ms准备、100ms接触段、250ms收势。成功后目标按360px/s移动共54px，受墙、箱、实体和合法落点约束。推撞本身不直接扣血。
- 推撞接触第二人可打断其当前起手并使其短暂失衡260ms，但不产生第二个推撞机会。
- 已经选择的追击/推撞承担落空风险；机会不会因按错方向或准备后目标脱离而自动返还。被击中会失去尚未消费的机会。

## 防御受压与合法起手

`hero.guardPressure` 取代旧2秒计数，范围0–100：普通挡击+40，精准招架-40。举刀期间完全不恢复。放下防御且距离上次受压/受伤已满1.2秒后，以20/秒恢复；不会松手瞬间清零。

普通挡击只作用于正面可防近战；火枪与炮弹必须走位/闪避。普通挡击有110ms接触硬直；压力到80时后滑加重，满100时破防并有650ms防御恢复约束。**满100且一直举刀，不能在650ms后重新无伤挡下一刀。必须放下防御，使压力降至100以下。** 满压状态通过 `snapshot.hero.guardBroken` 明确提供给UI；不能只看 `guardBrokenUntil`。

精准窗口140ms，只从合法的新防御起手产生：未成功招架后，两次合法起手至少间隔480ms；恢复中反复按K仅是普通举刀，不刷新窗口。持续按住K也不会刷新。成功招架后下一次合法起手最早在220ms后，供后续真实连招调校；当前敌人没有靠这条规则增加隐藏连招。

`snapshot.hero` 提供 `guardPressure`、`guardBroken`、`parryWindow`、`parryReadyAt`、`guardRecoveryRemaining`。旧 `blockTimes` 仅保留兼容数据，不再是破防依据。

## 两刀、确认取消与单槽缓存

| 动作 | 前摇 | 有效 | 总长 | 用途 |
| --- | --- | --- | --- | --- |
| 第一刀 | 100ms | 80ms | 420ms | 实际刀根约 `(35.767,-43.980)`、刀尖约 `(59.767,-47.227)` |
| 第二刀 | 150ms | 110ms | 560ms | 两个实际active刀段，短前进并将轻敌后逼12px |
| 空斩 | 35ms | 120ms | 300ms | 每次离地仅一次，落地重置 |

第二刀必须在第一刀有效命中后，再有一次明确J按下。持续按住攻击不会循环第一刀或自动进入第二刀。每个攻击ID对同一目标最多结算一次伤害。

第一刀、第二刀、空斩与刀兵有效攻击按同一 `sampleClipFrame` 的phaseFrames选帧，使用该帧真实刀根→刀尖线段与角色受击AABB的最近距离≤2px判定，已去除宽泛dy/中心reach伤害范围。推撞使用该帧真实前掌点。整个feet-local坐标组随朝向镜像。较高处挥刀可能擦中真实头部，也可能从头顶挥空，不以“楼层”硬编码伤害许可。

`public/assets/actors-v2/contact-geometry.json` 与生成的 `src/game/art-contact-data.ts` 由导入器同源输出，记录原始浮点与 `sourceManifestSha256`。回归校验当前manifest完整SHA、JSON/TS相等及每帧端点与实际rig公式一致；不是手工维护第二份攻击长度。

取消只在 `attack.hitConfirmed && elapsed>=activeEnd` 后开放，输出 `attack.cancelOpen`。第一刀确认后可衔接第二刀；已确认的刀可以取消到防御、跳离、正常闪避或已绑定的上下文动作。第二刀不能在确认窗口直接变成免费第三刀。取消不重置敌人有效受击累计，不刷新闪避冷却，不赠送无敌。

挥空没有上述取消权限，必须承担当次可见收势。`hero.inputBuffer` 只有一个槽，180ms有效，新输入覆盖旧输入；失焦、暂停、受伤、死亡和完成会清空。输入冲突优先级为：上下文、闪避、跳、防御、攻击；同一tick不会执行多条排队指令。暂留的旧 `jumpBufferedUntil` 不承担另一条隐藏缓存。

## 刀兵反制不依赖隐藏无敌

`enemy.effectiveLightHits` 统计同一压制段内的实际有效玩家轻击，不按第一/第二刀动画编号计数。J命中后取消防御再出第一刀，累计仍保留。

第二次有效轻击后，刀兵在220ms受击末尾进入 `brace`（收刀护身），准备160ms后才进入真正架稳的 `retreat`；后撤550ms，速度82px/s。准备过程仍然掉血；额外轻击不无限重置已经展示的护身准备进度。架稳后仅正面挡住普通刀，不获得全身无敌；后方、枪弹、炮弹仍按正常接触伤害。

护身/后撤有明确动作字段、`braceEstablished`、事件和帧读回。完成后撤，或真实拉开140px以上并保持500ms，才结束这一压制累计；玩家取消动作本身不会清空它。

刀兵起手520ms、有效150ms、收势650ms；起手前240ms可调整方向，之后锁向，不临时转身追踪。真正挥空会设置 `whiffRecovery`。倒下后取消尚未兑现的近战接触，已飞出的实体弹丸继续存在。

实际刀根距身体前方约40.6px。原宽范围判定移除后，曾从原始场景普通输入清枪手并贴近刀兵，再全部松手15秒，复现主角4HP不变、刀兵12次空挥。现用可见 `retreat` 身体动作做半步取距，`retreatKind:'spacing'` 与架稳护身的 `'guarded'` 区分。取距不格挡、不无敌、不清轻击累计，至少150ms且真实刀段可触才再起手；取距阶段可转向避开绕背后的堵身，进入攻击后仍遵循原锁向。出刀前进8px若会把目标挤到刀根内则不执行该前进。正常输入后松手回归验证已不再原地无限挥空。

## 闪避、弹道与同时伤害

- 闪避260ms，仅60–180ms中段免疫直接近战/枪弹/炮弹；起手与收势可受伤。独立800ms冷却，不因命中取消而清零。`invulnerableUntil` 只保存受伤后的700ms保护，闪避窗口独立计算。
- 五帧实际alpha高度49/51/51/64/70，碰撞与受击高度统一保留2px发缘，为47/49/49/62/68；帧时间60/60/60/40/40ms，起手0–60、中段60–180、收势180–260。`DODGE_TIMING`、`getDodgeFrame`与`getDodgeHeight`供画面与判定同源使用。不能按旧365ms条带时间截播，也不能在蹲姿空处保留整块站姿头部受击框。
- 可穿当前两种轻敌；墙、箱和横板仍有实体约束。先计算能站起的合法终点；通道不足就缩短，在结束时恢复68高并再次分离。没有重型兵/Boss的穿越承诺。
- 火枪端枪1000ms，前450ms选择左右朝向，之后锁定；开火120ms、装填1700ms。新专用端枪/开火身体与独立枪rig均为固定向下14°，实体弹丸沿真实root→muzzle方向发射；玩家高低移动不会暗改枪角或弹道。`aimX/Y`表达实际固定枪线上的点，不再是玩家身体坐标。
- `MUZZLES.musket` 从新fire接触记录生成，当前约 `{x:46.479509,y:-40.920389}`；炮按新长炮为 `{x:-43,y:-24}`。`getMusketLine(pose,'aim'|'fire')` 提供同源root、muzzle、direction，枪焰与实体弹丸共用真实枪口。
- 炮准备450ms、冷却1200ms，朝左780px/s；炮3伤害、枪1伤害，对敌我一致。完整线段扫掠先取最近实体/地形接触，不能因高速跨过薄板。
- 主角受伤700ms保护避免同时多个来源连续扣血。敌人没有为拖时长添加通用隐藏免疫。场景只有两名敌人，因此主要主动威胁上限为两条，没有额外刷怪或不可见导演伤害。

## 出口与两条可达解法

`model.encounter` 输出 `status:'active'|'exitReady'|'complete'`、`exitX:606`、`completedAt` 与 `routeFlags`。两名敌人倒下后出口可用；主角活着、落地且走到606才完成。没有强制最短计时、隐形等待、自动传送或必须用炮才能通关的条件。

模型输入回归从 `createModel()` 原始场景开始，决策只读实际动作与位置，每一步只提交正常输入，没有改坐标、HP、敌状态或计时器：

- **先远程**：越箱登台，在真实装填中断枪手并J追击；再回身退到真实刀刃距离处理刀兵，越台到出口。当前脚本熟练解法543tick、9.05秒，剩4HP，不用炮。
- **先炮线**：越箱到右侧甲板，退半步在真实刀段招架、同层E推撞刀兵，再换位抢炮并炮击刀兵；回高台断装填并追击枪手，走到出口。当前脚本熟练解法681tick、11.35秒，剩2HP。

这证明两种处理顺序与出口可达，**不是45–90秒首玩时长、真实浏览器/手机表现或用户手感验收**。45–90秒是首次读招与探索的待测目标，不能用延迟、刷怪或血量强行补齐。5人盲测尚未执行，没有替用户联系测试者。

## 验证边界

当前 `npm run check` 通过；47项模型、3项固定时钟、9项接触几何，共59项测试通过。覆盖压力、合法防御起手、机会来源/目标/消费、真实E前掌范围、过期E不点炮、缓存绑定与清理、确认取消与落空收势、取消后的真实轻击累计、可见护身/取距后撤、逐帧闪避高度和间隙、身体与地形、扫掠与敌我同伤、伤后保护、死亡重开、出口，以及两条无实体注入的自然输入路线。30/60/120/144Hz渲染切片重放同一普通输入时间线的完整snapshot一致。

模型中的动作帧和接触记录已同源校验，但测试通过不代替真实画面的动画/接触同步验收。新美术、桌面/手机真实输入、E误触、正常速度录像和首玩时长由后续浏览器与用户试玩验收；未通过前不扩章、不完成完整Goal。
