# 体验与界面草图（随核心规则评审调整）

本文件只锁定低负担与移动端要求，不代表行囊路线已通过。

## 1. 刚回来

主要画面是自己的林间小屋，而非任务和数字面板。屋前能看到已留下的陈设与熟悉伙伴。右侧或下方只放一张待寄信封和一个主要动作。首次进入用一句话说明：带一封信出门，沿途捎些故事回来。

不弹出签到、离线收益和补课列表。已有旅途时主要动作改为「继续这趟路」，保留地图、行囊和当前位置。

## 2. 整理行囊

四个容量格始终可见；每件工具标明占几格，以及当前路线上的具体用途。点选/取消即可，不要求拖动。出发前可以查看地图和主信目的地，不隐藏关键代价。

不要塞满四格才能继续，也不要把推荐配装设成唯一正确答案。超容量时阻止该次选择并给出短提示，允许随时换回。

## 3. 沿途选择

地图是可玩的主要画面。当前位置、已走路径、可到达节点、信件目的地分别清楚可见；故事卡不遮住当前路口。每个选项同一位置列出明确代价与得到/错过的机会。

每次行动最多一个短段落和两三个选择。走路的表现不承担强制等待；新动作确认后状态立即保存，过场可跳过，减少动态效果时直接显示结果。

## 4. 回家之后

结算回答三个问题：信送给了谁、沿途见到了谁、家里会多什么。以具体物件和伙伴记忆呈现，而非「战利品 +100、评分 A」。重复结果明确标为已拥有，不假装抽到新物件。

能直接把新陈设放到小屋，或稍后在收藏中找到。若没有送达也可回家，既有成长不倒扣；不要额外堆重试确认。

## 5. 平时闲看与保存

伙伴、藏品和布置各有入口，但不需要每天管理。默认在当前浏览器自动保存；提供导出/导入备份，并明确不跨设备自动同步。用户必须能把自己的成长带走。

音量控制在可找到的位置；音乐默认关闭，主动开启才播放，切后台暂停。帮助只在需要时展开，首页不放长规则说明。

## 视觉与输入标准

- 奶油纸色与深松绿配合现成像素素材。完整场景为视觉主体，不使用素材九宫格拼贴充数。
- 320px 与 390px 视口实际验证；地图可点击目标至少 44px；不依赖悬停、右键或精确拖拽。
- 桌面可并列场景与手记；手机先场景/当前选择，再可折叠的背包与说明，避免连续几屏文字挡住行动。
- 可点击项与静态陈设有明确区别；所有已拥有内容保持清楚，不套统一 disabled 透明度。
- 动效只帮助理解位置与结果；文字不逐字强制打出，任何设备都能立即阅读。
- 动物两帧可以呼吸/轻晃，但不冒充完整方向走路动画。减少动态效果或页面隐藏时停止非必要动画。

## 实现验收的底线

首局、刷新续玩、往返查看地图、合法/非法装包、路线走到尾端、结果只结算一次、永久成长、备份导入导出、损坏数据、两个标签页、窄屏、减少动态效果和音频主动播放都需实际验证。自动测试关注规则/保存边界；真实浏览器确认可理解和可操作。
